# Film Studio v1.0.0 — PWA Update Verification

Recorded from the CP5-02 Q04 slice (accepted by Q00, evidence SHA 70a4fe0).
This is the method and result behind the "auto-update" claim in the release
notes; it is not re-run in CP5-04 (docs-only).

## Setup

- Harness: `.private/perf/measure.mjs` (git-ignored) — Node static server with
  gzip serving the production `dist/` build, on a dedicated port.
- Browser: Playwright Chromium `channel:'chromium'` (ANGLE Metal), headless.
- Build: `npm run build`, service worker generated by vite-plugin-pwa
  (`registerType: 'autoUpdate'`, Workbox `generateSW`).

## Method

1. Load the built app; confirm the service worker installs and controls the
   page (`navigator.serviceWorker.controller` present after reload).
2. Fetch `/sw.js` and append a synthetic comment line (a byte change with no
   behavior change), so the served worker differs from the installed one.
3. Call `registration.update()`.
4. Wait for `controllerchange` (update activated; `autoUpdate` skips the waiting
   phase).
5. Reload and confirm the app boots normally from the new worker.

## Result — PASS

- `registration.update()` picked up the changed `sw.js`.
- `controllerchange` fired and the new worker took control.
- Post-update reload loaded the app successfully.

## Related cache measurements (same harness)

- Precache manifest after CP5-02: 53 entries, all unique URLs (was 73). Final
  raw precache size in the serial CP5 run is 12,346.27 KiB (was 24,082.93 KiB).
  Workbox already deduplicated duplicate URLs at install (server log showed 54
  unique
  cache writes from 73 entries), so the entry-count reduction is manifest
  clarity, while the measurable install win is the removal of
  `social-preview.png`: install transfer 4,100,872 B → 3,502,282 B (−14.6%).
  Report the transfer figure, not the entry-count percentage.
- Warm reload: 14/14 requests served by the service worker, 0 network bytes.
- Photo-only boot: 0 video-engine requests, 0 LUT requests on first open
  (the default profile's LUT is fetched by the viewport at boot, not on open).

## Constraints for future verification runs

- Perf/behavior runs need `channel:'chromium'`; the default headless shell
  (SwiftShader) is not valid for perf.
- Record machine load average; load >4 marks a contended run and numbers are
  not quoted as results.
- Service worker state persists per origin+profile; use a clean profile or
  unregister between runs.
